4  Source coding: compression

Information theory was born to solve telecommunication problems. A sender must transmit a message to a distant receiver through a channel — any physical means that carries signals. The sender first converts the message into a form suitable for the channel (encoding); the receiver reconstructs the message from what arrives (decoding). In a digital phone call, for instance, a sound is converted into a string of numbers and back.

A good encoding must satisfy two competing requirements:

  • it must allow faithful reconstruction of the message (minimal information loss);
  • it must be as short as possible, so as to maximise the information transmission rate.

Whatever the message (sound, image, text), the encoding converts it into the common currency of communication: a string of binary digits. Shannon’s motivation for defining entropy was to answer the question: what is the minimum number of binary digits per symbol needed to encode a source? This chapter proves that the answer is \(H(X)\), in two different settings:

  • lossy (fixed-length) coding: all codewords have the same length, but we accept that a small fraction of messages are lost — the error probability \(\delta\) can be made as small as we like;
  • lossless (variable-length, symbol) coding: every message is reconstructed exactly, but probable messages get short codewords and improbable ones long codewords.

Both rely on the same idea — exploiting the non-uniformity of \(p\) — and both give \(H(X)\) as the fundamental limit.

4.1 Raw bit content

Let the message \(x\) be drawn from a finite set \(\mathcal A_X = \{x_1, \ldots, x_N\}\) with probability \(p_X(x)\). A fixed-length binary code is a map \[E : \mathcal A_X \to \mathcal B^K, \qquad \mathcal B^K = \{0, 1\}^K,\] and decoding is \(D = E^{-1}\). For \(E\) to be invertible it must be injective; since \(|\mathcal B^K| = 2^K\), we need \(2^K \geq |\mathcal A_X|\): \[K \geq H_0(X) \equiv \log_2 |\mathcal A_X| .\]

\(H_0(X) = \log_2|\mathcal A_X|\) is the raw bit content of \(X\). By a simple counting argument, no invertible fixed-length code can use fewer than \(\lceil H_0 \rceil\) binary digits.

Toss a coin with \(P(h) = 0.9\), \(P(t) = 0.1\). Then \(H_0(X) = 1\) but \[H(X) = -0.9\log 0.9 - 0.1\log 0.1 \approx 0.47 \text{ bits}.\] To communicate one toss we must still use one binary digit (\(E: h \mapsto 0,\ t \mapsto 1\)). The information content of the outcome is less than half of the raw bit content, which suggests that one digit per toss is wasteful.

The intuition is correct, but the gain can only be realised for sequences of messages \(x^{(n)} = (x_1, \ldots, x_n) \in \mathcal A_X^n\), each drawn independently from the same source. There are then two ways to compress:

  • lossy coding: two different sequences may be mapped to the same codeword (or some sequences are discarded), but this happens with small probability;
  • lossless coding: use variable-length codewords of lengths \(\ell_x\). We cannot have \(\ell_x < H_0\) for all \(x\) (counting argument), but we can make the average \(\langle \ell \rangle = \sum_x p(x)\ell_x\) smaller than \(H_0\) by giving probable \(x\) short codewords.

4.2 Lossy coding

Consider sequences \(X^{(n)} = (X_1, \ldots, X_n)\) of i.i.d. symbols, i.e. a random vector in \(\mathcal A_X^n\), and a fixed-length code \(E^{(n)} : \mathcal A_X^n \to \mathcal B^K\). A perfectly faithful code needs \(K \geq H_0(X^{(n)}) = n H_0(X)\).

We now relax faithfulness. Choose a subset \(S \subset \mathcal A_X^n\) and assign codewords only to sequences in \(S\); sequences in \(\bar S\) are either discarded (\(E(x^{(n)}) = \emptyset\)) or mapped onto codewords already in use. The decoder makes an error exactly when \(x^{(n)} \in \bar S\), so the error probability is \[P_e = P\bigl(D(E(X^{(n)})) \neq X^{(n)}\bigr) = P(X^{(n)} \in \bar S).\]

For \(n = 3\) tosses with \(P(h) = 0.9\):

outcome \(hhh\) \(hht, hth, thh\) \(htt, tht, tth\) \(ttt\)
probability (each) \(0.729\) \(0.081\) \(0.009\) \(0.001\)

\(H(X^{(3)}) = 3H(X) \approx 1.41\) bits while \(H_0(X^{(3)}) = 3\). The invertible code \[hhh \mapsto 000,\ hht \mapsto 001,\ hth \mapsto 010,\ thh \mapsto 100,\ htt \mapsto 011,\ tht \mapsto 101,\ tth \mapsto 110,\ ttt \mapsto 111\] uses \(K = 3\) and has \(P_e = 0\). But the outcomes with two or more tails have total probability \(3(0.009) + 0.001 = 0.028\). If we keep only \[S = \{hhh, hht, hth, thh\}, \qquad \tilde E : hhh \mapsto 00,\ hht \mapsto 01,\ hth \mapsto 10,\ thh \mapsto 11,\] and send nothing for the other outcomes, we use only 2 digits at the price of \(P_e = 2.8\%\).

To keep the error below a tolerance \(\delta\), \(S\) must be \(\delta\)-sufficient: \(P(X^{(n)} \in S) \geq 1 - \delta\).

The smallest \(\delta\)-sufficient subset is \[S_\delta(X^{(n)}) = \arg\min_{S} \bigl\{ |S| \;:\; S \subseteq \mathcal A_X^n,\ P(X^{(n)} \in S) \geq 1 - \delta \bigr\}.\] It is obtained by sorting the outcomes by decreasing probability and keeping the first \(k\) of them, stopping as soon as their cumulative probability reaches \(1 - \delta\). The essential bit content is \[H_\delta(X^{(n)}) = \log_2 |S_\delta(X^{(n)})| ,\] the number of binary digits needed if we tolerate error probability \(\delta\).

Adding outcomes in order of decreasing probability:

\(\delta\) range \(|S_\delta|\) \(H_\delta\) (bits)
\(0 \leq \delta < 0.001\) 8 3.00
\(0.001 \leq \delta < 0.010\) 7 2.81
\(0.010 \leq \delta < 0.019\) 6 2.58
\(0.019 \leq \delta < 0.028\) 5 2.32
\(0.028 \leq \delta < 0.109\) 4 2.00
\(0.109 \leq \delta < 0.190\) 3 1.58
\(0.190 \leq \delta < 0.271\) 2 1.00
\(0.271 \leq \delta < 1\) 1 0.00

\(H_\delta\) is a decreasing staircase function of \(\delta\); at \(n = 3\) it depends strongly on \(\delta\).

4.2.1 What happens as \(n\) grows

Plot \(H_\delta(X^{(n)})/n\) against \(\delta\) for increasing \(n\) (MacKay, Fig. 4.9; Allegra, Fig. 3.1). As \(n\) grows the curves become flatter and flatter and collapse onto the horizontal line \(H_\delta/n = H(X)\). This has two consequences:

  1. Achievability. Fix a small tolerance \(\delta_1\). For large \(n\), \(H_{\delta_1}(X^{(n)})/n = H(X) + \beta\) with \(\beta \ll 1\): the smallest \(\delta_1\)-sufficient subset has about \(2^{n(H + \beta)}\) elements, and a code with that many codewords — about \(H(X)\) digits per symbol — has error at most \(\delta_1\). For the \(p = 0.9\) coin with \(n = 1000\), \(\delta_1 = 0.05\) gives \(\beta \approx 0.05\), i.e. about \(0.51\) digits per toss instead of 1.
  2. Converse. Fix a small \(\beta\). For large \(n\), \(H_\delta/n < H(X) - \beta\) only when \(\delta \to 1\): using fewer than \(2^{n(H - \beta)}\) codewords means losing almost every message.

One can code with vanishing error using \(H(X)\) digits per symbol, but not fewer. The mechanism behind this is typicality.

4.3 Typicality and the AEP

In a long sequence each symbol \(x_i\) appears, with high probability, roughly \(m_i \approx n p_i\) times. For the biased coin, sequences of length \(n\) have about \(0.9n\) heads and \(0.1n\) tails. The probability of such a sequence is \[P(x^{(n)}) \approx p_1^{np_1}\, p_2^{np_2} \cdots p_N^{np_N} = 2^{n\sum_i p_i \log p_i} = 2^{-nH(X)},\] so its information content is \(-\log P(x^{(n)}) \approx nH(X)\). These are the typical sequences.

For \(\beta > 0\), the set of \((n, \beta)\)-typical sequences is \[T_{n\beta} = \Bigl\{ x^{(n)} \in \mathcal A_X^n \;:\; \Bigl|\,{-\tfrac{1}{n}\log_2 P(x^{(n)}) - H(X)}\Bigr| < \beta \Bigr\}.\] Equivalently, \(2^{-n(H + \beta)} < P(x^{(n)}) < 2^{-n(H - \beta)}\).

For \(X_1, X_2, \ldots\) i.i.d. \(\sim p\):

  1. \(-\tfrac{1}{n}\log_2 P(X_1, \ldots, X_n) \to H(X)\) in probability as \(n \to \infty\).
  2. \(P(X^{(n)} \in T_{n\beta}) \to 1\) as \(n \to \infty\), for any \(\beta > 0\).
  3. \(|T_{n\beta}| < 2^{n(H + \beta)}\), and \(|T_{n\beta}| > (1 - \epsilon)2^{n(H - \beta)}\) for \(n\) large enough.

So almost all probability concentrates on roughly \(2^{nH}\) sequences, which are (to exponential accuracy) equiprobable — hence equipartition. Since there are \(2^{nH_0} = |\mathcal A_X|^n\) sequences in total, the typical set is an exponentially small fraction \(2^{-n(H_0 - H)}\) of all sequences, yet it carries almost all the probability.

Take \(n = 100\), \(p(h) = 0.9\). Typical sequences have about 10 tails; their number is \(\binom{100}{10} \approx 1.7 \times 10^{13} \approx 2^{44}\), close to \(2^{nH} = 2^{46.9}\) (the agreement improves with \(n\)). There are \(2^{100}\) sequences in total. Each typical sequence has probability \(\approx 2^{-47}\).

Note that the single most probable sequence, \(hh\cdots h\), with \(P = 0.9^{100} \approx 2.7 \times 10^{-5}\), is not typical: \(-\tfrac1n \log P = 0.152 \ll H = 0.469\). It is very likely compared to any single typical sequence, but there is only one of it, while typical sequences are astronomically many. The histogram of the number of tails \(m\) concentrates around \(m = 10\) with width \(\sqrt{np(1-p)} = 3\); relative to \(n\), the width shrinks as \(1/\sqrt n\).

Remark (Physical meaning). The AEP is the information-theoretic analogue of the equivalence of ensembles in statistical mechanics: a system with fixed temperature (canonical) has, with overwhelming probability, an energy close to its mean, so it behaves like a microcanonical ensemble of \(\approx e^{S}\) equiprobable microstates. Here \(nH\) plays the role of the entropy \(S\).

4.4 Shannon’s source coding theorem

4.4.1 Intuitive argument

  1. We have sequences \(X^{(n)}\) of i.i.d. messages from the same source.
  2. We want a lossy fixed-length code with error at most \(\delta\): we must identify \(S_\delta(X^{(n)})\); codewords have length \(H_\delta = \log|S_\delta|\).
  3. For large \(n\), a random sequence is almost surely typical, and each typical sequence has \(P \approx 2^{-nH}\). Since their probabilities add up to nearly 1, there are \(\approx 2^{nH}\) of them.
  4. Hence a \(\delta\)-sufficient subset made of typical sequences has size \(\approx 2^{nH}\), and the smallest one can be no larger: codewords of length \(\approx nH\) suffice.
  5. Codewords cannot be much shorter. With length \(n(H - \Delta)\) there are at most \(2^{n(H - \Delta)}\) codewords; since nearly all the probability sits on typical sequences of probability \(\approx 2^{-nH}\) each, the covered probability is at most \(2^{n(H - \Delta)} 2^{-nH} = 2^{-n\Delta} \to 0\). The error tends to 1.

4.4.2 Rigorous statement and proof

Let \(X\) have entropy \(H = H(X)\). For every \(\delta \in (0, 1)\) and every \(\beta > 0\) there exists \(n_0\) such that for all \(n > n_0\), \[\Bigl|\frac{H_\delta(X^{(n)})}{n} - H\Bigr| < \beta .\]

In words: for long enough sequences, lossy compression with arbitrarily small error is possible with \(n(H + \beta)\) bits, i.e. \(2^{n(H + \beta)}\) codewords; compression with \(n(H - \beta)\) bits is impossible unless we accept an error probability arbitrarily close to 1. Consequently:

  • the information in \(n\) i.i.d. realisations of \(X\) can be transmitted with \(\approx H(X)\) binary digits per realisation, with asymptotically vanishing loss;
  • it cannot be compressed further.

The proof has three parts.

Part I — typical sequences are typical. \[P(X^{(n)} \in T_{n\beta}) \geq 1 - \frac{\sigma^2}{n\beta^2}, \qquad \sigma^2 = \operatorname{Var}[-\log p(X_i)] .\]

Proof. Recall Chebyshev’s inequality \(P((Z - \mathbb E Z)^2 \geq \alpha) \leq \operatorname{Var}(Z)/\alpha\). For the mean \(M_n = \tfrac1n \sum_i Z_i\) of i.i.d. variables, \(\mathbb E M_n = \mathbb E Z\) and \(\operatorname{Var} M_n = \operatorname{Var}Z/n\), so \[P\bigl((M_n - \mathbb E Z)^2 < \alpha\bigr) \geq 1 - \frac{\operatorname{Var} Z}{n\alpha}.\] Let \(I_i = -\log p(X_i)\), the information content of the \(i\)-th symbol: these are i.i.d. with mean \(H\) and variance \(\sigma^2\). Because the symbols are independent, \[\bar I^{(n)} \equiv -\tfrac1n\log P(X^{(n)}) = -\tfrac1n\sum_i \log p(X_i) = \tfrac1n\sum_i I_i ,\] a mean of i.i.d. variables. Since \(X^{(n)} \in T_{n\beta} \iff (\bar I^{(n)} - H)^2 < \beta^2\), Chebyshev with \(\alpha = \beta^2\) gives the claim. (This is the weak law of large numbers for \(\bar I^{(n)}\), i.e. part 1 of the AEP.)

Part II — achievability: for all \(\delta, \beta\) there is \(n_1\) such that \(H_\delta(X^{(n)}) < n(H + \beta)\) for all \(n > n_1\).

Proof. Take \(n_1 > \sigma^2/(\beta^2\delta)\). By Part I, for \(n > n_1\), \(P(X^{(n)} \in T_{n\beta}) > 1 - \delta\): the typical set is \(\delta\)-sufficient, so \(|S_\delta| \leq |T_{n\beta}|\). Every typical sequence has \(P(x^{(n)}) > 2^{-n(H + \beta)}\), hence \[1 \geq P(T_{n\beta}) > |T_{n\beta}|\,2^{-n(H + \beta)} \quad\Rightarrow\quad |T_{n\beta}| < 2^{n(H + \beta)} .\] Therefore \(H_\delta = \log|S_\delta| \leq \log|T_{n\beta}| < n(H + \beta)\).

Part III — converse: for all \(\delta, \beta\) there is \(n_2\) such that \(H_\delta(X^{(n)}) > n(H - \beta)\) for all \(n > n_2\).

Proof. Suppose, for contradiction, that some set \(S\) with \(|S| \leq 2^{n(H - \beta)}\) is \(\delta\)-sufficient. Split it into its typical and atypical parts with respect to the narrower set \(T_{n,\beta/2}\): \[P(X^{(n)} \in S) = P(X^{(n)} \in S \cap T_{n,\beta/2}) + P(X^{(n)} \in S \cap \bar T_{n,\beta/2}).\] Every sequence in \(T_{n,\beta/2}\) has \(P(x^{(n)}) < 2^{-n(H - \beta/2)}\), so the first term is at most \[|S|\,2^{-n(H - \beta/2)} \leq 2^{n(H - \beta)}\,2^{-n(H - \beta/2)} = 2^{-n\beta/2}.\] The second term is at most \(P(X^{(n)} \notin T_{n,\beta/2}) \leq 4\sigma^2/(n\beta^2)\) by Part I. Hence \[P(X^{(n)} \in S) \leq 2^{-n\beta/2} + \frac{4\sigma^2}{n\beta^2},\] which decreases to zero; for \(n\) large enough it is below \(1 - \delta\), contradicting \(\delta\)-sufficiency. So \(|S_\delta| > 2^{n(H - \beta)}\).

Combining Parts II and III with \(n_0 = \max(n_1, n_2)\) proves the theorem. \(\blacksquare\)

Remark (How large must \(n\) be?). Part II requires \(n \gtrsim \sigma^2/(\beta^2\delta)\): lossy fixed-length coding is efficient only for very long blocks. For the \(p = 0.9\) coin, \(\sigma^2 = p(1-p)\bigl(\log\tfrac{p}{1-p}\bigr)^2 = 0.09 \times (\log_2 9)^2 \approx 0.90\), so \(\beta = 0.1\) and \(\delta = 0.01\) require \(n \approx 10^4\). (Chebyshev is pessimistic; sharper Chernoff bounds give exponential convergence, but the message stands.) This motivates lossless variable-length codes, which work symbol by symbol.

Remark (Rate–distortion theory). The lossy coding above is “lossy” only in that a vanishing fraction of messages is lost. In engineering, “lossy compression” (JPEG, MP3) usually means something different: every message is reconstructed approximately, with an average distortion \(D\). The optimal trade-off is the rate–distortion function \(R(D) = \min_{p(\hat x | x) : \mathbb E d(X, \hat X) \leq D} I(X; \hat X)\) (Cover & Thomas, Ch. 10). For a Gaussian source with variance \(\sigma^2\) and squared error, \(R(D) = \tfrac12\log_2(\sigma^2/D)\) for \(D \leq \sigma^2\). We will not develop this theory further.

4.5 Lossless coding: symbol codes

A symbol code maps each symbol to a binary string of variable length: \[E : \mathcal A_X \to \mathcal B^+, \qquad \mathcal B^+ = \mathcal B \cup \mathcal B^2 \cup \mathcal B^3 \cup \cdots,\] \(x_i \mapsto y_i \in \mathcal B^{\ell_i}\); \(y_i\) is the codeword and \(\ell_i\) the codeword length. It extends to sequences \(x^+ \in \mathcal A_X^+ = \mathcal A_X \cup \mathcal A_X^2 \cup \cdots\) by concatenation, \[E^+(x_{i_1}x_{i_2}\cdots x_{i_n}) = E(x_{i_1})E(x_{i_2})\cdots E(x_{i_n}).\]

For the coin, \(E : h \mapsto 0,\ t \mapsto 101\) (lengths 1 and 3) gives \(E^+(hhh) = 000\), \(E^+(ht) = 0101\), etc.

A good symbol code should be

  • uniquely decodable (invertible on sequences),
  • easy to decode,
  • short on average: the expected length \(L(E, X) = \sum_i p_i \ell_i\) should be minimal.

4.5.1 Unique decodability

\(E\) is uniquely decodable if \(E^+\) is injective: \(x^+ \neq x'^+ \Rightarrow E^+(x^+) \neq E^+(x'^+)\).

Distinct codewords are necessary but not sufficient.

\(h \mapsto 0,\ t \mapsto 101\) is uniquely decodable: \(0101101000101\) decodes only as \(htthhht\) (every \(1\) starts a \(101\)). But for \(\mathcal A = \{a, b, c, d\}\) with \[a \mapsto 0,\ b \mapsto 1,\ c \mapsto 00,\ d \mapsto 11,\] the string \(0011011\) can be read as \(cdad\), \(aadad\), \(aabbad\) or \(aabbabb\). All codewords are distinct, yet the code is not uniquely decodable.

4.5.2 Prefix codes

“Easy to decode” means that each codeword can be recognised as soon as its last bit arrives, without looking ahead. This requires that no codeword be a prefix of another (\(c\) is a prefix of \(d\) if \(d = ct\) for some string \(t\); e.g. \(1\) and \(10\) are prefixes of \(101\)).

A code is a prefix code (also instantaneous or self-punctuating) if no codeword is a prefix of another codeword.

\(a \mapsto 1,\ b \mapsto 101\) is uniquely decodable (each \(0\) signals a \(b\)). But on receiving \(110111\) (\(= abaa\)), after the first \(1\) we cannot yet decide between \(a\) and the beginning of \(b\); we must wait for the third digit. The culprit is that \(1\) is a prefix of \(101\). The code \(a \mapsto 0,\ b \mapsto 101\) is a prefix code and decodes instantaneously.

Every prefix code is uniquely decodable. In particular, fixed-length codes with distinct codewords are uniquely decodable.

Proof. Suppose \(E^+(x_1 \cdots x_k) = E^+(y_1 \cdots y_l)\) with \(x \neq y\). Strip the longest common initial run of symbols (\(x_i = y_i\) for \(i \leq m\)); the remaining sequences still have equal encodings, and now \(x_{m+1} \neq y_{m+1}\) (the remainders cannot both be empty since \(x \neq y\)). Both encoded strings begin with \(E(x_{m+1})\) and \(E(y_{m+1})\) respectively. If these have equal length they are equal, so two symbols share a codeword; if not, the shorter is a prefix of the longer. Either way the code is not a prefix code.

Prefix codes are binary trees. Take a probability tree in which every branching has exactly two children, \(E = E_0 \cup E_1\), and label the edges \(0\) and \(1\). Reading the labels from the root to a leaf gives a binary string; assigning these strings to the leaves gives a prefix code, because a prefix of a codeword corresponds to an internal node, which is not a leaf. Conversely every prefix code defines such a tree.

\(X \in \{0, 1, 2, 3\}\) with \(p = (\tfrac12, \tfrac14, \tfrac18, \tfrac18)\). The tree “is it 0? / is it 1? / is it 2?” gives the prefix code \[0 \mapsto 0, \quad 1 \mapsto 10, \quad 2 \mapsto 110, \quad 3 \mapsto 111,\] with \(L = \tfrac12 \cdot 1 + \tfrac14 \cdot 2 + 2 \cdot \tfrac18 \cdot 3 = 1.75\) bits \(= H(X)\). Here \(L = H\) because \(\ell_i = -\log p_i\) exactly; this is possible only when all \(p_i\) are powers of \(1/2\).

For \(X^{(3)}\) (three tosses, \(p(h) = 0.9\)), let \(M\) be the number of tails: \(p_M = (0.729, 0.243, 0.027, 0.001)\). Ask “\(M = 0\)?”, then “\(M = 1\)?”, then “\(M = 2\)?”. If \(M = 1\) or \(2\), two more binary questions identify which of the three arrangements occurred. Reading edge labels gives \[hhh \mapsto 0,\ hht \mapsto 100,\ thh \mapsto 1010,\ hth \mapsto 1011,\ htt \mapsto 1100,\ tht \mapsto 11010,\ tth \mapsto 11011,\ ttt \mapsto 111,\] with expected length \[L = 0.729 \cdot 1 + 0.081 \cdot 3 + 2(0.081) \cdot 4 + 0.009 \cdot 4 + 2(0.009) \cdot 5 + 0.001 \cdot 3 = 1.749 \text{ bits},\] much better than the 3 bits of the fixed-length code and not far from \(H(X^{(3)}) = 1.41\).

4.5.3 Kraft’s inequality

Short average length comes from giving probable outcomes short codewords. We cannot make all codewords short: unique decodability constrains the lengths.

If a binary code is uniquely decodable, its codeword lengths satisfy \[\sum_i 2^{-\ell_i} \leq 1 .\] Conversely, for any lengths satisfying this inequality there exists a prefix code with those lengths.

A code with \(\sum_i 2^{-\ell_i} = 1\) is called complete. Prefix codes read off a full binary tree are complete: replace every edge probability by \(1/2\); the leaf at depth \(\ell_i\) then gets probability \(q_i = 2^{-\ell_i}\), and these probabilities must sum to one. For the three-toss tree above, \(\sum 2^{-\ell_i} = 2^{-1} + 2\cdot 2^{-3} + 3 \cdot 2^{-4} + 2 \cdot 2^{-5} = 2^{-5}(16 + 8 + 6 + 2) = 1\).

Proof (Proof of necessity (McMillan)). Let \(S = \sum_i 2^{-\ell_i}\). Then \[S^n = \sum_{i_1, \ldots, i_n} 2^{-(\ell_{i_1} + \cdots + \ell_{i_n})},\] where \(\ell_{i_1} + \cdots + \ell_{i_n}\) is the length of the encoding of the string \(x_{i_1}\cdots x_{i_n}\). With \(\ell_{\min}, \ell_{\max}\) the shortest and longest codeword lengths, group the terms by total length \(\ell\): \[S^n = \sum_{\ell = n\ell_{\min}}^{n\ell_{\max}} 2^{-\ell} |A_\ell|,\] where \(A_\ell\) is the set of length-\(n\) source strings encoded into \(\ell\) bits. Unique decodability forces \(|A_\ell| \leq 2^\ell\) (there are only \(2^\ell\) binary strings of length \(\ell\)). Hence \[S^n \leq \sum_{\ell = n\ell_{\min}}^{n\ell_{\max}} 1 \leq n\ell_{\max}.\] If \(S > 1\), the left side grows exponentially in \(n\) while the right side grows linearly — impossible for large \(n\). So \(S \leq 1\).

Proof (Proof of sufficiency). Let \(A_\ell\) now denote the number of required codewords of length \(\ell\); the inequality reads \(\sum_\ell A_\ell 2^{-\ell} \leq 1\). Assign codewords in order of increasing length, keeping the prefix property at every stage. Suppose the codewords of length up to \(\ell\) have been chosen. Each codeword of length \(\ell' \leq \ell\) is a prefix of \(2^{\ell + 1 - \ell'}\) strings of length \(\ell + 1\), which are forbidden. The number of available strings of length \(\ell + 1\) is therefore \[2^{\ell+1} - \sum_{\ell' \leq \ell} A_{\ell'}\,2^{\ell+1-\ell'},\] and we can pick \(A_{\ell+1}\) of them iff \(\sum_{\ell' \leq \ell + 1} A_{\ell'}\,2^{-\ell'} \leq 1\) — which follows from Kraft’s inequality. Starting from the shortest length (no constraints) and inducting gives a prefix code.

Remark. Kraft’s inequality is necessary for unique decodability, not sufficient: mapping every symbol to the single codeword \(0\) (with \(|\mathcal A| = 2\), \(2^{-1} + 2^{-1} = 1\)) satisfies it but is obviously not decodable. The sufficiency statement says that some prefix code with those lengths exists. A key consequence: nothing is gained by using uniquely decodable codes that are not prefix codes — prefix codes achieve every set of lengths that any uniquely decodable code can.

4.6 Source coding theorem for symbol codes

For any uniquely decodable code, \[L(E, X) \geq H(X),\] with equality iff \(\ell_i = -\log_2 p_i\) for all \(i\). Moreover there exists a prefix code with \[H(X) \leq L(E, X) < H(X) + 1 .\]

Proof. Lower bound. Define the “implicit probabilities” of the code \(q_i = 2^{-\ell_i}/z\), with \(z = \sum_j 2^{-\ell_j} \leq 1\) by Kraft. Then \[D_{KL}(p \| q) = \sum_i p_i \log\frac{p_i}{q_i} = -H(X) + \sum_i p_i \ell_i + \log z ,\] so \[L(E, X) = H(X) + D_{KL}(p \| q) - \log z \geq H(X) + D_{KL}(p\|q) \geq H(X).\] Equality requires (1) \(z = 1\), a complete code, and (2) \(p = q\), i.e. \(p_i = 2^{-\ell_i}\).

Upper bound. Condition (2) can be met exactly only if all \(p_i\) are negative powers of 2, but the identity suggests choosing \(\ell_i \approx -\log p_i\). Take the Shannon code lengths \(\ell_i = \lceil -\log_2 p_i \rceil\). They satisfy Kraft, \[\sum_i 2^{-\lceil -\log p_i\rceil} \leq \sum_i 2^{\log p_i} = \sum_i p_i = 1,\] so a prefix code with these lengths exists, and \[L = \sum_i p_i \lceil -\log p_i \rceil < \sum_i p_i(-\log p_i + 1) = H(X) + 1 .\]

The identity \(L = H + D(p\|q) - \log z\) gives a precise meaning to the KL divergence of Chapter 2: a complete code designed for the distribution \(q\) but used on a source \(p\) wastes exactly \(D(p\|q)\) bits per symbol.

\(p = (0.4, 0.35, 0.2, 0.05)\): \(-\log p = (1.32, 1.51, 2.32, 4.32)\), so Shannon lengths are \((2, 2, 3, 5)\) and \(L = 0.8 + 0.7 + 0.6 + 0.25 = 2.35\) bits, against \(H = 1.74\) bits. The bound \(L < H + 1\) holds, but the code is far from optimal — Huffman (below) does better.

Applying the theorem to blocks \(X^{(n)}\) of \(n\) i.i.d. symbols, whose entropy is \(nH\), gives a code with \(nH \leq L_n < nH + 1\), i.e. a rate per symbol \[H(X) \leq \frac{L_n}{n} < H(X) + \frac1n .\] The overhead of at most one bit is spread over \(n\) symbols and becomes negligible.

4.7 Huffman codes

Shannon codes satisfy the bounds but are not optimal. Huffman’s algorithm constructs an optimal prefix code by building the binary tree from the leaves up.

Given probabilities \(p_1, \ldots, p_N\):

  1. Create a node for each outcome.
  2. Take the two least probable parentless nodes and create a parent node for them, with probability equal to their sum. Label the two edges 0 and 1.
  3. Repeat step 2 until a single root remains. The codeword of each leaf is the string of labels from the root to the leaf.

By construction the two least probable outcomes are siblings and get codewords of equal length.

\(p = (0.4, 0.35, 0.2, 0.05)\), \(H \approx 1.74\) bits. Merges: \(0.05 + 0.2 = 0.25\); \(0.25 + 0.35 = 0.60\); \(0.60 + 0.4 = 1\). Codewords \(0, 10, 110, 111\) with lengths \((1, 2, 3, 3)\) and \(L = 0.4 + 0.7 + 0.6 + 0.15 = 1.85\) bits — \(0.5\) bits better than the Shannon code above, and only \(0.11\) above \(H\).

For \(X^{(3)}\) with \(p(h) = 0.9\), Huffman’s algorithm gives \[hhh \mapsto 0,\ hht \mapsto 100,\ hth \mapsto 101,\ thh \mapsto 110,\ htt \mapsto 11110,\ tht \mapsto 11100,\ tth \mapsto 11101,\ ttt \mapsto 11111,\] with \[L = 0.729 \cdot 1 + 3(0.081)\cdot 3 + 3(0.009)\cdot 5 + 0.001 \cdot 5 = 1.598 \text{ bits},\] better than the tree code above (1.749) and closer to \(H(X^{(3)}) = 1.41\). Per toss: \(0.53\) bits, versus \(H(X) = 0.47\).

No uniquely decodable code for the same source has smaller expected length than the Huffman code. In particular \(H(X) \leq L^{Huff} < H(X) + 1\).

Proof. Order \(p_1 \leq p_2 \leq \cdots \leq p_N\). By the Kraft–McMillan theorem we may restrict to prefix codes, and an optimal prefix code may be taken complete (otherwise some codeword could be shortened).

Step 1: in some optimal code, the two least probable symbols are siblings of maximal length. In a complete prefix code the deepest leaves come in sibling pairs. If \(\ell_1\) were not maximal, some \(x_j\) with \(p_j \geq p_1\) would sit deeper; swapping \(x_1\) and \(x_j\) changes \(L\) by \((\ell_1 - \ell_j)(p_j - p_1) \leq 0\), so it does not hurt. Likewise we can place \(x_2\) in the sibling slot of \(x_1\) without increasing \(L\). (If \(\ell_{1} > \ell_2\) in an optimal code and some \(x_3\) with \(p_3 > p_2\) had length \(\ell_1\), swapping \(x_2\) and \(x_3\) would change \(L\) by \((\ell_1 - \ell_2)(p_2 - p_3) < 0\), contradicting optimality.)

Step 2: induction on \(N\). For \(N = 2\) any code uses two codewords of length 1, which is optimal. Assume Huffman is optimal for \(N - 1\) symbols. Take an optimal tree for \((p_1, \ldots, p_N)\) in which \(x_1, x_2\) are siblings and merge them: this gives a tree for \((p_1 + p_2, p_3, \ldots, p_N)\), with \[L_{\text{opt}}(p_1, \ldots, p_N) = L(p_1 + p_2, p_3, \ldots, p_N) + p_1 + p_2,\] since the merged codeword is one bit shorter for both. The merged tree must be optimal for the reduced source (otherwise unmerging a better one would beat the optimum). The Huffman tree for \((p_1, \ldots, p_N)\) merges \(x_1, x_2\) first and then is the Huffman tree for the reduced source, which is optimal by the induction hypothesis. So both satisfy the same relation with the same reduced optimal length, and \(L^{Huff}(p_1, \ldots, p_N) = L_{\text{opt}}(p_1, \ldots, p_N)\).

4.8 Beyond symbol codes

Symbol codes waste up to one bit per symbol, which is a lot when \(H(X) \ll 1\) (e.g. the \(p = 0.99\) coin, \(H = 0.08\) bits, still needs one bit per symbol). Two remedies are used in practice:

  • Arithmetic coding encodes a whole sequence as a sub-interval of \([0, 1)\) of width \(P(x^{(n)})\), which needs about \(-\log P(x^{(n)})\) bits: the overhead is \(O(1)\) bits per message rather than per symbol, and it adapts naturally to probabilities that change from symbol to symbol (e.g. from a predictive model).
  • Universal codes (Lempel–Ziv, context-tree weighting) do not need to know \(p\) at all: they learn the statistics from the data as they go.

Lempel–Ziv coding, applied to a stationary ergodic source of entropy rate \(H_\infty\), achieves an asymptotic compression rate of \(H_\infty\) bits per symbol without any advance knowledge of the source.

Remark. gzip, bzip2 and xz are variations on Lempel–Ziv and Huffman/arithmetic coding. The theoretical guarantee that they reach the entropy limit is a consequence of the AEP for ergodic sequences (Chapter 6).

4.9 Exercises

Construct a Huffman code for a source with probabilities \((1/2, 1/4, 1/8, 1/16, 1/16)\) and verify it achieves \(H(X)\).

Solution. \(H(X) = 0.5 + 0.5 + 0.375 + 0.25 + 0.25 = 1.875\) bits. Huffman merges \(1/16 + 1/16 = 1/8\), then \(1/8 + 1/8 = 1/4\), then \(1/4 + 1/4 = 1/2\), then \(1/2 + 1/2\). Codewords \(0, 10, 110, 1110, 1111\), lengths \((1, 2, 3, 4, 4)\), \(L = 1/2 + 1/2 + 3/8 + 1/4 + 1/4 = 1.875\) bits. Exactly \(H\) — because all probabilities are dyadic.

Show that \(\sum_i 2^{-\ell_i} = 1\) for a complete prefix code (one where every internal node of the tree has two children).

Solution. Replace every edge probability by \(1/2\). A leaf at depth \(\ell_i\) then has probability \(2^{-\ell_i}\); since the leaves of a full binary tree partition the root event, these probabilities sum to 1. A tree with a missing child has a “hole” of probability \(2^{-d}\) and gives strict inequality.

Is the code \(\{0, 01, 011, 0111\}\) uniquely decodable? Is it a prefix code? Does it satisfy Kraft?

Solution. Not a prefix code (\(0\) is a prefix of all others). It is uniquely decodable: every codeword starts with \(0\), so each \(0\) marks the start of a new codeword and the number of following \(1\)s identifies it — but decoding needs one bit of lookahead. Kraft: \(1/2 + 1/4 + 1/8 + 1/16 = 15/16 \leq 1\). By Kraft–McMillan, the prefix code \(\{0, 10, 110, 1110\}\) (the reversed codewords) has the same lengths.

For the \(p = 0.9\) coin, compare the expected length per toss of the Huffman code on blocks of \(n = 1, 2, 3\) tosses with \(H(X) = 0.469\).

Solution. \(n = 1\): 1 bit/toss. \(n = 2\): probabilities \((0.81, 0.09, 0.09, 0.01)\); Huffman lengths \((1, 2, 3, 3)\), \(L_2 = 0.81 + 0.18 + 0.27 + 0.03 = 1.29\), i.e. \(0.645\) bits/toss. \(n = 3\): \(L_3 = 1.598\), i.e. \(0.533\) bits/toss. The rate approaches \(H\) as \(n\) grows, consistent with \(L_n/n < H + 1/n\).

A code designed for \(q = (\tfrac12, \tfrac14, \tfrac18, \tfrac18)\) (lengths \(1, 2, 3, 3\)) is used on a uniform source \(p = (\tfrac14, \tfrac14, \tfrac14, \tfrac14)\). Compute the expected length and check it equals \(H(p) + D(p\|q)\).

Solution. \(L = \tfrac14(1 + 2 + 3 + 3) = 2.25\) bits. \(H(p) = 2\) and \(D(p\|q) = \tfrac14[\log\tfrac{1/4}{1/2} + \log 1 + 2\log\tfrac{1/4}{1/8}] = \tfrac14[-1 + 0 + 2] = 0.25\). Indeed \(2 + 0.25 = 2.25\) (the code is complete, \(z = 1\)).

4.10 Callouts

The fixed-length source-coding theorem is asymptotic: it needs \(n \sim \sigma^2/(\beta^2\delta)\). Symbol codes work with \(n = 1\) but can waste up to one bit per symbol; coding blocks of \(n\) symbols reduces this to \(1/n\).

Useful mental picture: an optimal code assigns \(\ell_i \approx -\log_2 p_i\), i.e. codeword length = surprisal. Conversely, every complete prefix code implicitly defines a probability model \(q_i = 2^{-\ell_i}\).

The most probable sequence is not typical. Typicality is about the information content \(-\tfrac1n\log P\), not about the probability being large.

Universal codes give the asymptotic compression rate. On short inputs they often expand the data due to header overhead. Don’t benchmark compressors on toy examples.

Information theory was born to solve telecommunication problems. A **sender** must transmit a message to a distant **receiver** through a **channel** — any physical means that carries signals. The sender first converts the message into a form suitable for the channel (**encoding**); the receiver reconstructs the message from what arrives (**decoding**). In a digital phone call, for instance, a sound is converted into a string of numbers and back.

A good encoding must satisfy two competing requirements:

- it must allow **faithful reconstruction** of the message (minimal information loss);
- it must be **as short as possible**, so as to maximise the information transmission rate.

Whatever the message (sound, image, text), the encoding converts it into the common currency of communication: a **string of binary digits**. Shannon's motivation for defining entropy was to answer the question: *what is the minimum number of binary digits per symbol needed to encode a source?* This chapter proves that the answer is $H(X)$, in two different settings:

- **lossy (fixed-length) coding**: all codewords have the same length, but we accept that a small fraction of messages are lost — the error probability $\delta$ can be made as small as we like;
- **lossless (variable-length, symbol) coding**: every message is reconstructed exactly, but probable messages get short codewords and improbable ones long codewords.

Both rely on the same idea — exploiting the non-uniformity of $p$ — and both give $H(X)$ as the fundamental limit.

## Raw bit content

Let the message $x$ be drawn from a finite set $\mathcal A_X = \{x_1, \ldots, x_N\}$ with probability $p_X(x)$. A **fixed-length binary code** is a map
$$E : \mathcal A_X \to \mathcal B^K, \qquad \mathcal B^K = \{0, 1\}^K,$$
and decoding is $D = E^{-1}$. For $E$ to be invertible it must be injective; since $|\mathcal B^K| = 2^K$, we need $2^K \geq |\mathcal A_X|$:
$$K \geq H_0(X) \equiv \log_2 |\mathcal A_X| .$$

::: {.definition name="Raw bit content"}
$H_0(X) = \log_2|\mathcal A_X|$ is the **raw bit content** of $X$. By a simple counting argument, no invertible fixed-length code can use fewer than $\lceil H_0 \rceil$ binary digits.
:::

::: {.example name="A biased coin"}
Toss a coin with $P(h) = 0.9$, $P(t) = 0.1$. Then $H_0(X) = 1$ but
$$H(X) = -0.9\log 0.9 - 0.1\log 0.1 \approx 0.47 \text{ bits}.$$
To communicate one toss we must still use one binary digit ($E: h \mapsto 0,\ t \mapsto 1$). The information content of the outcome is less than half of the raw bit content, which suggests that one digit per toss is wasteful.
:::

The intuition is correct, but the gain can only be realised for **sequences** of messages $x^{(n)} = (x_1, \ldots, x_n) \in \mathcal A_X^n$, each drawn independently from the same source. There are then two ways to compress:

- **lossy coding:** two different sequences may be mapped to the same codeword (or some sequences are discarded), but this happens with small probability;
- **lossless coding:** use variable-length codewords of lengths $\ell_x$. We cannot have $\ell_x < H_0$ for *all* $x$ (counting argument), but we can make the *average* $\langle \ell \rangle = \sum_x p(x)\ell_x$ smaller than $H_0$ by giving probable $x$ short codewords.

## Lossy coding

Consider sequences $X^{(n)} = (X_1, \ldots, X_n)$ of i.i.d. symbols, i.e. a random vector in $\mathcal A_X^n$, and a fixed-length code $E^{(n)} : \mathcal A_X^n \to \mathcal B^K$. A perfectly faithful code needs $K \geq H_0(X^{(n)}) = n H_0(X)$.

We now relax faithfulness. Choose a subset $S \subset \mathcal A_X^n$ and assign codewords only to sequences in $S$; sequences in $\bar S$ are either discarded ($E(x^{(n)}) = \emptyset$) or mapped onto codewords already in use. The decoder makes an error exactly when $x^{(n)} \in \bar S$, so the **error probability** is
$$P_e = P\bigl(D(E(X^{(n)})) \neq X^{(n)}\bigr) = P(X^{(n)} \in \bar S).$$

::: {.example name="Three tosses of the biased coin"}
For $n = 3$ tosses with $P(h) = 0.9$:

| outcome | $hhh$ | $hht, hth, thh$ | $htt, tht, tth$ | $ttt$ |
|:---|:---:|:---:|:---:|:---:|
| probability (each) | $0.729$ | $0.081$ | $0.009$ | $0.001$ |

$H(X^{(3)}) = 3H(X) \approx 1.41$ bits while $H_0(X^{(3)}) = 3$. The invertible code
$$hhh \mapsto 000,\ hht \mapsto 001,\ hth \mapsto 010,\ thh \mapsto 100,\ htt \mapsto 011,\ tht \mapsto 101,\ tth \mapsto 110,\ ttt \mapsto 111$$
uses $K = 3$ and has $P_e = 0$. But the outcomes with two or more tails have total probability $3(0.009) + 0.001 = 0.028$. If we keep only
$$S = \{hhh, hht, hth, thh\}, \qquad \tilde E : hhh \mapsto 00,\ hht \mapsto 01,\ hth \mapsto 10,\ thh \mapsto 11,$$
and send nothing for the other outcomes, we use only **2 digits** at the price of $P_e = 2.8\%$.
:::

To keep the error below a tolerance $\delta$, $S$ must be **$\delta$-sufficient**: $P(X^{(n)} \in S) \geq 1 - \delta$.

::: {.definition name="Smallest δ-sufficient subset and essential bit content"}
The **smallest $\delta$-sufficient subset** is
$$S_\delta(X^{(n)}) = \arg\min_{S} \bigl\{ |S| \;:\; S \subseteq \mathcal A_X^n,\ P(X^{(n)} \in S) \geq 1 - \delta \bigr\}.$$
It is obtained by sorting the outcomes by decreasing probability and keeping the first $k$ of them, stopping as soon as their cumulative probability reaches $1 - \delta$. The **essential bit content** is
$$H_\delta(X^{(n)}) = \log_2 |S_\delta(X^{(n)})| ,$$
the number of binary digits needed if we tolerate error probability $\delta$.
:::

::: {.example name="Essential bit content for three tosses"}
Adding outcomes in order of decreasing probability:

| $\delta$ range | $|S_\delta|$ | $H_\delta$ (bits) |
|:---|:---:|:---:|
| $0 \leq \delta < 0.001$ | 8 | 3.00 |
| $0.001 \leq \delta < 0.010$ | 7 | 2.81 |
| $0.010 \leq \delta < 0.019$ | 6 | 2.58 |
| $0.019 \leq \delta < 0.028$ | 5 | 2.32 |
| $0.028 \leq \delta < 0.109$ | 4 | 2.00 |
| $0.109 \leq \delta < 0.190$ | 3 | 1.58 |
| $0.190 \leq \delta < 0.271$ | 2 | 1.00 |
| $0.271 \leq \delta < 1$ | 1 | 0.00 |

$H_\delta$ is a decreasing staircase function of $\delta$; at $n = 3$ it depends strongly on $\delta$.
:::

### What happens as $n$ grows

Plot $H_\delta(X^{(n)})/n$ against $\delta$ for increasing $n$ (MacKay, Fig. 4.9; Allegra, Fig. 3.1). As $n$ grows the curves become flatter and flatter and collapse onto the horizontal line $H_\delta/n = H(X)$. This has two consequences:

1. **Achievability.** Fix a small tolerance $\delta_1$. For large $n$, $H_{\delta_1}(X^{(n)})/n = H(X) + \beta$ with $\beta \ll 1$: the smallest $\delta_1$-sufficient subset has about $2^{n(H + \beta)}$ elements, and a code with that many codewords — about $H(X)$ digits per symbol — has error at most $\delta_1$. For the $p = 0.9$ coin with $n = 1000$, $\delta_1 = 0.05$ gives $\beta \approx 0.05$, i.e. about $0.51$ digits per toss instead of 1.
2. **Converse.** Fix a small $\beta$. For large $n$, $H_\delta/n < H(X) - \beta$ only when $\delta \to 1$: using fewer than $2^{n(H - \beta)}$ codewords means losing almost every message.

**One can code with vanishing error using $H(X)$ digits per symbol, but not fewer.** The mechanism behind this is typicality.

## Typicality and the AEP

In a long sequence each symbol $x_i$ appears, with high probability, roughly $m_i \approx n p_i$ times. For the biased coin, sequences of length $n$ have about $0.9n$ heads and $0.1n$ tails. The probability of such a sequence is
$$P(x^{(n)}) \approx p_1^{np_1}\, p_2^{np_2} \cdots p_N^{np_N} = 2^{n\sum_i p_i \log p_i} = 2^{-nH(X)},$$
so its information content is $-\log P(x^{(n)}) \approx nH(X)$. These are the **typical sequences**.

::: {.definition name="Typical set"}
For $\beta > 0$, the set of **$(n, \beta)$-typical sequences** is
$$T_{n\beta} = \Bigl\{ x^{(n)} \in \mathcal A_X^n \;:\; \Bigl|\,{-\tfrac{1}{n}\log_2 P(x^{(n)}) - H(X)}\Bigr| < \beta \Bigr\}.$$
Equivalently, $2^{-n(H + \beta)} < P(x^{(n)}) < 2^{-n(H - \beta)}$.
:::

::: {.theorem name="Asymptotic Equipartition Property (AEP)"}
For $X_1, X_2, \ldots$ i.i.d. $\sim p$:

1. $-\tfrac{1}{n}\log_2 P(X_1, \ldots, X_n) \to H(X)$ in probability as $n \to \infty$.
2. $P(X^{(n)} \in T_{n\beta}) \to 1$ as $n \to \infty$, for any $\beta > 0$.
3. $|T_{n\beta}| < 2^{n(H + \beta)}$, and $|T_{n\beta}| > (1 - \epsilon)2^{n(H - \beta)}$ for $n$ large enough.
:::

So almost all probability concentrates on roughly $2^{nH}$ sequences, which are (to exponential accuracy) **equiprobable** — hence *equipartition*. Since there are $2^{nH_0} = |\mathcal A_X|^n$ sequences in total, the typical set is an exponentially small fraction $2^{-n(H_0 - H)}$ of all sequences, yet it carries almost all the probability.

::: {.example name="Typicality for 100 tosses"}
Take $n = 100$, $p(h) = 0.9$. Typical sequences have about 10 tails; their number is $\binom{100}{10} \approx 1.7 \times 10^{13} \approx 2^{44}$, close to $2^{nH} = 2^{46.9}$ (the agreement improves with $n$). There are $2^{100}$ sequences in total. Each typical sequence has probability $\approx 2^{-47}$.

Note that the **single most probable sequence**, $hh\cdots h$, with $P = 0.9^{100} \approx 2.7 \times 10^{-5}$, is *not* typical: $-\tfrac1n \log P = 0.152 \ll H = 0.469$. It is very likely compared to any *single* typical sequence, but there is only one of it, while typical sequences are astronomically many. The histogram of the number of tails $m$ concentrates around $m = 10$ with width $\sqrt{np(1-p)} = 3$; relative to $n$, the width shrinks as $1/\sqrt n$.
:::

::: {.remark name="Physical meaning"}
The AEP is the information-theoretic analogue of the equivalence of ensembles in statistical mechanics: a system with fixed temperature (canonical) has, with overwhelming probability, an energy close to its mean, so it behaves like a microcanonical ensemble of $\approx e^{S}$ equiprobable microstates. Here $nH$ plays the role of the entropy $S$.
:::

## Shannon's source coding theorem

### Intuitive argument

1. We have sequences $X^{(n)}$ of i.i.d. messages from the same source.
2. We want a lossy fixed-length code with error at most $\delta$: we must identify $S_\delta(X^{(n)})$; codewords have length $H_\delta = \log|S_\delta|$.
3. For large $n$, a random sequence is almost surely typical, and each typical sequence has $P \approx 2^{-nH}$. Since their probabilities add up to nearly 1, there are $\approx 2^{nH}$ of them.
4. Hence a $\delta$-sufficient subset made of typical sequences has size $\approx 2^{nH}$, and the *smallest* one can be no larger: codewords of length $\approx nH$ suffice.
5. Codewords cannot be much shorter. With length $n(H - \Delta)$ there are at most $2^{n(H - \Delta)}$ codewords; since nearly all the probability sits on typical sequences of probability $\approx 2^{-nH}$ each, the covered probability is at most $2^{n(H - \Delta)} 2^{-nH} = 2^{-n\Delta} \to 0$. The error tends to 1.

### Rigorous statement and proof

::: {.theorem name="Shannon's source coding theorem"}
Let $X$ have entropy $H = H(X)$. For every $\delta \in (0, 1)$ and every $\beta > 0$ there exists $n_0$ such that for all $n > n_0$,
$$\Bigl|\frac{H_\delta(X^{(n)})}{n} - H\Bigr| < \beta .$$
:::

In words: for long enough sequences, lossy compression with arbitrarily small error is possible with $n(H + \beta)$ bits, i.e. $2^{n(H + \beta)}$ codewords; compression with $n(H - \beta)$ bits is impossible unless we accept an error probability arbitrarily close to 1. Consequently:

- the information in $n$ i.i.d. realisations of $X$ can be transmitted with $\approx H(X)$ binary digits per realisation, with asymptotically vanishing loss;
- it cannot be compressed further.

The proof has three parts.

**Part I — typical sequences are typical.**
$$P(X^{(n)} \in T_{n\beta}) \geq 1 - \frac{\sigma^2}{n\beta^2}, \qquad \sigma^2 = \operatorname{Var}[-\log p(X_i)] .$$

::: {.proof}
Recall Chebyshev's inequality $P((Z - \mathbb E Z)^2 \geq \alpha) \leq \operatorname{Var}(Z)/\alpha$. For the mean $M_n = \tfrac1n \sum_i Z_i$ of i.i.d. variables, $\mathbb E M_n = \mathbb E Z$ and $\operatorname{Var} M_n = \operatorname{Var}Z/n$, so
$$P\bigl((M_n - \mathbb E Z)^2 < \alpha\bigr) \geq 1 - \frac{\operatorname{Var} Z}{n\alpha}.$$
Let $I_i = -\log p(X_i)$, the information content of the $i$-th symbol: these are i.i.d. with mean $H$ and variance $\sigma^2$. Because the symbols are independent,
$$\bar I^{(n)} \equiv -\tfrac1n\log P(X^{(n)}) = -\tfrac1n\sum_i \log p(X_i) = \tfrac1n\sum_i I_i ,$$
a mean of i.i.d. variables. Since $X^{(n)} \in T_{n\beta} \iff (\bar I^{(n)} - H)^2 < \beta^2$, Chebyshev with $\alpha = \beta^2$ gives the claim. (This is the weak law of large numbers for $\bar I^{(n)}$, i.e. part 1 of the AEP.)
:::

**Part II — achievability:** for all $\delta, \beta$ there is $n_1$ such that $H_\delta(X^{(n)}) < n(H + \beta)$ for all $n > n_1$.

::: {.proof}
Take $n_1 > \sigma^2/(\beta^2\delta)$. By Part I, for $n > n_1$, $P(X^{(n)} \in T_{n\beta}) > 1 - \delta$: the typical set is $\delta$-sufficient, so $|S_\delta| \leq |T_{n\beta}|$. Every typical sequence has $P(x^{(n)}) > 2^{-n(H + \beta)}$, hence
$$1 \geq P(T_{n\beta}) > |T_{n\beta}|\,2^{-n(H + \beta)} \quad\Rightarrow\quad |T_{n\beta}| < 2^{n(H + \beta)} .$$
Therefore $H_\delta = \log|S_\delta| \leq \log|T_{n\beta}| < n(H + \beta)$.
:::

**Part III — converse:** for all $\delta, \beta$ there is $n_2$ such that $H_\delta(X^{(n)}) > n(H - \beta)$ for all $n > n_2$.

::: {.proof}
Suppose, for contradiction, that some set $S$ with $|S| \leq 2^{n(H - \beta)}$ is $\delta$-sufficient. Split it into its typical and atypical parts with respect to the narrower set $T_{n,\beta/2}$:
$$P(X^{(n)} \in S) = P(X^{(n)} \in S \cap T_{n,\beta/2}) + P(X^{(n)} \in S \cap \bar T_{n,\beta/2}).$$
Every sequence in $T_{n,\beta/2}$ has $P(x^{(n)}) < 2^{-n(H - \beta/2)}$, so the first term is at most
$$|S|\,2^{-n(H - \beta/2)} \leq 2^{n(H - \beta)}\,2^{-n(H - \beta/2)} = 2^{-n\beta/2}.$$
The second term is at most $P(X^{(n)} \notin T_{n,\beta/2}) \leq 4\sigma^2/(n\beta^2)$ by Part I. Hence
$$P(X^{(n)} \in S) \leq 2^{-n\beta/2} + \frac{4\sigma^2}{n\beta^2},$$
which decreases to zero; for $n$ large enough it is below $1 - \delta$, contradicting $\delta$-sufficiency. So $|S_\delta| > 2^{n(H - \beta)}$.
:::

Combining Parts II and III with $n_0 = \max(n_1, n_2)$ proves the theorem. $\blacksquare$

::: {.remark name="How large must $n$ be?"}
Part II requires $n \gtrsim \sigma^2/(\beta^2\delta)$: lossy fixed-length coding is efficient only for very long blocks. For the $p = 0.9$ coin, $\sigma^2 = p(1-p)\bigl(\log\tfrac{p}{1-p}\bigr)^2 = 0.09 \times (\log_2 9)^2 \approx 0.90$, so $\beta = 0.1$ and $\delta = 0.01$ require $n \approx 10^4$. (Chebyshev is pessimistic; sharper Chernoff bounds give exponential convergence, but the message stands.) This motivates *lossless* variable-length codes, which work symbol by symbol.
:::

::: {.remark name="Rate–distortion theory"}
The lossy coding above is "lossy" only in that a vanishing fraction of messages is lost. In engineering, "lossy compression" (JPEG, MP3) usually means something different: every message is reconstructed *approximately*, with an average distortion $D$. The optimal trade-off is the **rate–distortion function** $R(D) = \min_{p(\hat x | x) : \mathbb E d(X, \hat X) \leq D} I(X; \hat X)$ (Cover & Thomas, Ch. 10). For a Gaussian source with variance $\sigma^2$ and squared error, $R(D) = \tfrac12\log_2(\sigma^2/D)$ for $D \leq \sigma^2$. We will not develop this theory further.
:::

## Lossless coding: symbol codes

A **symbol code** maps each symbol to a binary string of variable length:
$$E : \mathcal A_X \to \mathcal B^+, \qquad \mathcal B^+ = \mathcal B \cup \mathcal B^2 \cup \mathcal B^3 \cup \cdots,$$
$x_i \mapsto y_i \in \mathcal B^{\ell_i}$; $y_i$ is the **codeword** and $\ell_i$ the **codeword length**. It extends to sequences $x^+ \in \mathcal A_X^+ = \mathcal A_X \cup \mathcal A_X^2 \cup \cdots$ by concatenation,
$$E^+(x_{i_1}x_{i_2}\cdots x_{i_n}) = E(x_{i_1})E(x_{i_2})\cdots E(x_{i_n}).$$

::: {.example}
For the coin, $E : h \mapsto 0,\ t \mapsto 101$ (lengths 1 and 3) gives $E^+(hhh) = 000$, $E^+(ht) = 0101$, etc.
:::

A good symbol code should be

- **uniquely decodable** (invertible on sequences),
- **easy to decode**,
- **short on average**: the expected length $L(E, X) = \sum_i p_i \ell_i$ should be minimal.

### Unique decodability

::: {.definition name="Uniquely decodable code"}
$E$ is **uniquely decodable** if $E^+$ is injective: $x^+ \neq x'^+ \Rightarrow E^+(x^+) \neq E^+(x'^+)$.
:::

Distinct codewords are necessary but not sufficient.

::: {.example name="Distinct codewords are not enough"}
$h \mapsto 0,\ t \mapsto 101$ is uniquely decodable: $0101101000101$ decodes only as $htthhht$ (every $1$ starts a $101$). But for $\mathcal A = \{a, b, c, d\}$ with
$$a \mapsto 0,\ b \mapsto 1,\ c \mapsto 00,\ d \mapsto 11,$$
the string $0011011$ can be read as $cdad$, $aadad$, $aabbad$ or $aabbabb$. All codewords are distinct, yet the code is not uniquely decodable.
:::

### Prefix codes

"Easy to decode" means that each codeword can be recognised as soon as its last bit arrives, without looking ahead. This requires that no codeword be a **prefix** of another ($c$ is a prefix of $d$ if $d = ct$ for some string $t$; e.g. $1$ and $10$ are prefixes of $101$).

::: {.definition name="Prefix code"}
A code is a **prefix code** (also *instantaneous* or *self-punctuating*) if no codeword is a prefix of another codeword.
:::

::: {.example name="Uniquely decodable but not instantaneous"}
$a \mapsto 1,\ b \mapsto 101$ is uniquely decodable (each $0$ signals a $b$). But on receiving $110111$ ($= abaa$), after the first $1$ we cannot yet decide between $a$ and the beginning of $b$; we must wait for the third digit. The culprit is that $1$ is a prefix of $101$. The code $a \mapsto 0,\ b \mapsto 101$ is a prefix code and decodes instantaneously.
:::

::: {.proposition}
Every prefix code is uniquely decodable. In particular, fixed-length codes with distinct codewords are uniquely decodable.
:::

::: {.proof}
Suppose $E^+(x_1 \cdots x_k) = E^+(y_1 \cdots y_l)$ with $x \neq y$. Strip the longest common initial run of symbols ($x_i = y_i$ for $i \leq m$); the remaining sequences still have equal encodings, and now $x_{m+1} \neq y_{m+1}$ (the remainders cannot both be empty since $x \neq y$). Both encoded strings begin with $E(x_{m+1})$ and $E(y_{m+1})$ respectively. If these have equal length they are equal, so two symbols share a codeword; if not, the shorter is a prefix of the longer. Either way the code is not a prefix code.
:::

**Prefix codes are binary trees.** Take a probability tree in which every branching has exactly two children, $E = E_0 \cup E_1$, and label the edges $0$ and $1$. Reading the labels from the root to a leaf gives a binary string; assigning these strings to the leaves gives a prefix code, because a prefix of a codeword corresponds to an *internal* node, which is not a leaf. Conversely every prefix code defines such a tree.

::: {.example name="A dyadic source"}
$X \in \{0, 1, 2, 3\}$ with $p = (\tfrac12, \tfrac14, \tfrac18, \tfrac18)$. The tree "is it 0? / is it 1? / is it 2?" gives the prefix code
$$0 \mapsto 0, \quad 1 \mapsto 10, \quad 2 \mapsto 110, \quad 3 \mapsto 111,$$
with $L = \tfrac12 \cdot 1 + \tfrac14 \cdot 2 + 2 \cdot \tfrac18 \cdot 3 = 1.75$ bits $= H(X)$. Here $L = H$ because $\ell_i = -\log p_i$ exactly; this is possible only when all $p_i$ are powers of $1/2$.
:::

::: {.example name="A tree code for three tosses"}
For $X^{(3)}$ (three tosses, $p(h) = 0.9$), let $M$ be the number of tails: $p_M = (0.729, 0.243, 0.027, 0.001)$. Ask "$M = 0$?", then "$M = 1$?", then "$M = 2$?". If $M = 1$ or $2$, two more binary questions identify which of the three arrangements occurred. Reading edge labels gives
$$hhh \mapsto 0,\ hht \mapsto 100,\ thh \mapsto 1010,\ hth \mapsto 1011,\ htt \mapsto 1100,\ tht \mapsto 11010,\ tth \mapsto 11011,\ ttt \mapsto 111,$$
with expected length
$$L = 0.729 \cdot 1 + 0.081 \cdot 3 + 2(0.081) \cdot 4 + 0.009 \cdot 4 + 2(0.009) \cdot 5 + 0.001 \cdot 3 = 1.749 \text{ bits},$$
much better than the 3 bits of the fixed-length code and not far from $H(X^{(3)}) = 1.41$.
:::

### Kraft's inequality

Short average length comes from giving probable outcomes short codewords. We cannot make *all* codewords short: unique decodability constrains the lengths.

::: {.theorem name="Kraft–McMillan inequality"}
If a binary code is uniquely decodable, its codeword lengths satisfy
$$\sum_i 2^{-\ell_i} \leq 1 .$$
Conversely, for any lengths satisfying this inequality there exists a **prefix** code with those lengths.
:::

A code with $\sum_i 2^{-\ell_i} = 1$ is called **complete**. Prefix codes read off a full binary tree are complete: replace every edge probability by $1/2$; the leaf at depth $\ell_i$ then gets probability $q_i = 2^{-\ell_i}$, and these probabilities must sum to one. For the three-toss tree above, $\sum 2^{-\ell_i} = 2^{-1} + 2\cdot 2^{-3} + 3 \cdot 2^{-4} + 2 \cdot 2^{-5} = 2^{-5}(16 + 8 + 6 + 2) = 1$.

::: {.proof name="Proof of necessity (McMillan)"}
Let $S = \sum_i 2^{-\ell_i}$. Then
$$S^n = \sum_{i_1, \ldots, i_n} 2^{-(\ell_{i_1} + \cdots + \ell_{i_n})},$$
where $\ell_{i_1} + \cdots + \ell_{i_n}$ is the length of the encoding of the string $x_{i_1}\cdots x_{i_n}$. With $\ell_{\min}, \ell_{\max}$ the shortest and longest codeword lengths, group the terms by total length $\ell$:
$$S^n = \sum_{\ell = n\ell_{\min}}^{n\ell_{\max}} 2^{-\ell} |A_\ell|,$$
where $A_\ell$ is the set of length-$n$ source strings encoded into $\ell$ bits. Unique decodability forces $|A_\ell| \leq 2^\ell$ (there are only $2^\ell$ binary strings of length $\ell$). Hence
$$S^n \leq \sum_{\ell = n\ell_{\min}}^{n\ell_{\max}} 1 \leq n\ell_{\max}.$$
If $S > 1$, the left side grows exponentially in $n$ while the right side grows linearly — impossible for large $n$. So $S \leq 1$.
:::

::: {.proof name="Proof of sufficiency"}
Let $A_\ell$ now denote the number of required codewords of length $\ell$; the inequality reads $\sum_\ell A_\ell 2^{-\ell} \leq 1$. Assign codewords in order of increasing length, keeping the prefix property at every stage. Suppose the codewords of length up to $\ell$ have been chosen. Each codeword of length $\ell' \leq \ell$ is a prefix of $2^{\ell + 1 - \ell'}$ strings of length $\ell + 1$, which are forbidden. The number of available strings of length $\ell + 1$ is therefore
$$2^{\ell+1} - \sum_{\ell' \leq \ell} A_{\ell'}\,2^{\ell+1-\ell'},$$
and we can pick $A_{\ell+1}$ of them iff $\sum_{\ell' \leq \ell + 1} A_{\ell'}\,2^{-\ell'} \leq 1$ — which follows from Kraft's inequality. Starting from the shortest length (no constraints) and inducting gives a prefix code.
:::

::: {.remark}
Kraft's inequality is *necessary* for unique decodability, not sufficient: mapping every symbol to the single codeword $0$ (with $|\mathcal A| = 2$, $2^{-1} + 2^{-1} = 1$) satisfies it but is obviously not decodable. The sufficiency statement says that *some* prefix code with those lengths exists. A key consequence: **nothing is gained by using uniquely decodable codes that are not prefix codes** — prefix codes achieve every set of lengths that any uniquely decodable code can.
:::

## Source coding theorem for symbol codes

::: {.theorem name="Source coding theorem for symbol codes"}
For any uniquely decodable code,
$$L(E, X) \geq H(X),$$
with equality iff $\ell_i = -\log_2 p_i$ for all $i$. Moreover there exists a prefix code with
$$H(X) \leq L(E, X) < H(X) + 1 .$$
:::

::: {.proof}
*Lower bound.* Define the "implicit probabilities" of the code $q_i = 2^{-\ell_i}/z$, with $z = \sum_j 2^{-\ell_j} \leq 1$ by Kraft. Then
$$D_{KL}(p \| q) = \sum_i p_i \log\frac{p_i}{q_i} = -H(X) + \sum_i p_i \ell_i + \log z ,$$
so
$$L(E, X) = H(X) + D_{KL}(p \| q) - \log z \geq H(X) + D_{KL}(p\|q) \geq H(X).$$
Equality requires (1) $z = 1$, a complete code, and (2) $p = q$, i.e. $p_i = 2^{-\ell_i}$.

*Upper bound.* Condition (2) can be met exactly only if all $p_i$ are negative powers of 2, but the identity suggests choosing $\ell_i \approx -\log p_i$. Take the **Shannon code lengths** $\ell_i = \lceil -\log_2 p_i \rceil$. They satisfy Kraft,
$$\sum_i 2^{-\lceil -\log p_i\rceil} \leq \sum_i 2^{\log p_i} = \sum_i p_i = 1,$$
so a prefix code with these lengths exists, and
$$L = \sum_i p_i \lceil -\log p_i \rceil < \sum_i p_i(-\log p_i + 1) = H(X) + 1 .$$
:::

The identity $L = H + D(p\|q) - \log z$ gives a precise meaning to the KL divergence of Chapter 2: **a complete code designed for the distribution $q$ but used on a source $p$ wastes exactly $D(p\|q)$ bits per symbol.**

::: {.example name="Shannon code for a non-dyadic source"}
$p = (0.4, 0.35, 0.2, 0.05)$: $-\log p = (1.32, 1.51, 2.32, 4.32)$, so Shannon lengths are $(2, 2, 3, 5)$ and $L = 0.8 + 0.7 + 0.6 + 0.25 = 2.35$ bits, against $H = 1.74$ bits. The bound $L < H + 1$ holds, but the code is far from optimal — Huffman (below) does better.
:::

::: {.proposition name="Block coding closes the gap"}
Applying the theorem to blocks $X^{(n)}$ of $n$ i.i.d. symbols, whose entropy is $nH$, gives a code with $nH \leq L_n < nH + 1$, i.e. a rate per symbol
$$H(X) \leq \frac{L_n}{n} < H(X) + \frac1n .$$
The overhead of at most one bit is spread over $n$ symbols and becomes negligible.
:::

## Huffman codes

Shannon codes satisfy the bounds but are not optimal. **Huffman's algorithm** constructs an *optimal* prefix code by building the binary tree from the leaves up.

::: {.definition name="Huffman coding algorithm"}
Given probabilities $p_1, \ldots, p_N$:

1. Create a node for each outcome.
2. Take the two least probable parentless nodes and create a parent node for them, with probability equal to their sum. Label the two edges 0 and 1.
3. Repeat step 2 until a single root remains. The codeword of each leaf is the string of labels from the root to the leaf.
:::

By construction the two least probable outcomes are siblings and get codewords of equal length.

::: {.example name="Huffman for a skewed source"}
$p = (0.4, 0.35, 0.2, 0.05)$, $H \approx 1.74$ bits. Merges: $0.05 + 0.2 = 0.25$; $0.25 + 0.35 = 0.60$; $0.60 + 0.4 = 1$. Codewords $0, 10, 110, 111$ with lengths $(1, 2, 3, 3)$ and $L = 0.4 + 0.7 + 0.6 + 0.15 = 1.85$ bits — $0.5$ bits better than the Shannon code above, and only $0.11$ above $H$.
:::

::: {.example name="Huffman for three tosses"}
For $X^{(3)}$ with $p(h) = 0.9$, Huffman's algorithm gives
$$hhh \mapsto 0,\ hht \mapsto 100,\ hth \mapsto 101,\ thh \mapsto 110,\ htt \mapsto 11110,\ tht \mapsto 11100,\ tth \mapsto 11101,\ ttt \mapsto 11111,$$
with
$$L = 0.729 \cdot 1 + 3(0.081)\cdot 3 + 3(0.009)\cdot 5 + 0.001 \cdot 5 = 1.598 \text{ bits},$$
better than the tree code above (1.749) and closer to $H(X^{(3)}) = 1.41$. Per toss: $0.53$ bits, versus $H(X) = 0.47$.
:::

::: {.theorem name="Huffman optimality"}
No uniquely decodable code for the same source has smaller expected length than the Huffman code. In particular $H(X) \leq L^{Huff} < H(X) + 1$.
:::

::: {.proof}
Order $p_1 \leq p_2 \leq \cdots \leq p_N$. By the Kraft–McMillan theorem we may restrict to prefix codes, and an optimal prefix code may be taken complete (otherwise some codeword could be shortened).

*Step 1: in some optimal code, the two least probable symbols are siblings of maximal length.* In a complete prefix code the deepest leaves come in sibling pairs. If $\ell_1$ were not maximal, some $x_j$ with $p_j \geq p_1$ would sit deeper; swapping $x_1$ and $x_j$ changes $L$ by $(\ell_1 - \ell_j)(p_j - p_1) \leq 0$, so it does not hurt. Likewise we can place $x_2$ in the sibling slot of $x_1$ without increasing $L$. (If $\ell_{1} > \ell_2$ in an optimal code and some $x_3$ with $p_3 > p_2$ had length $\ell_1$, swapping $x_2$ and $x_3$ would change $L$ by $(\ell_1 - \ell_2)(p_2 - p_3) < 0$, contradicting optimality.)

*Step 2: induction on $N$.* For $N = 2$ any code uses two codewords of length 1, which is optimal. Assume Huffman is optimal for $N - 1$ symbols. Take an optimal tree for $(p_1, \ldots, p_N)$ in which $x_1, x_2$ are siblings and merge them: this gives a tree for $(p_1 + p_2, p_3, \ldots, p_N)$, with
$$L_{\text{opt}}(p_1, \ldots, p_N) = L(p_1 + p_2, p_3, \ldots, p_N) + p_1 + p_2,$$
since the merged codeword is one bit shorter for both. The merged tree must be optimal for the reduced source (otherwise unmerging a better one would beat the optimum). The Huffman tree for $(p_1, \ldots, p_N)$ merges $x_1, x_2$ first and then *is* the Huffman tree for the reduced source, which is optimal by the induction hypothesis. So both satisfy the same relation with the same reduced optimal length, and $L^{Huff}(p_1, \ldots, p_N) = L_{\text{opt}}(p_1, \ldots, p_N)$.
:::

## Beyond symbol codes

Symbol codes waste up to one bit per symbol, which is a lot when $H(X) \ll 1$ (e.g. the $p = 0.99$ coin, $H = 0.08$ bits, still needs one bit per symbol). Two remedies are used in practice:

- **Arithmetic coding** encodes a whole sequence as a sub-interval of $[0, 1)$ of width $P(x^{(n)})$, which needs about $-\log P(x^{(n)})$ bits: the overhead is $O(1)$ bits *per message* rather than per symbol, and it adapts naturally to probabilities that change from symbol to symbol (e.g. from a predictive model).
- **Universal codes** (Lempel–Ziv, context-tree weighting) do not need to know $p$ at all: they learn the statistics from the data as they go.

::: {.proposition name="LZ universality"}
Lempel–Ziv coding, applied to a stationary ergodic source of entropy rate $H_\infty$, achieves an asymptotic compression rate of $H_\infty$ bits per symbol without any advance knowledge of the source.
:::

::: {.remark}
gzip, bzip2 and xz are variations on Lempel–Ziv and Huffman/arithmetic coding. The theoretical guarantee that they reach the entropy limit is a consequence of the AEP for ergodic sequences (Chapter 6).
:::

## Exercises

::: {.exercise}
Construct a Huffman code for a source with probabilities $(1/2, 1/4, 1/8, 1/16, 1/16)$ and verify it achieves $H(X)$.
:::

::: {.solution}
$H(X) = 0.5 + 0.5 + 0.375 + 0.25 + 0.25 = 1.875$ bits. Huffman merges $1/16 + 1/16 = 1/8$, then $1/8 + 1/8 = 1/4$, then $1/4 + 1/4 = 1/2$, then $1/2 + 1/2$. Codewords $0, 10, 110, 1110, 1111$, lengths $(1, 2, 3, 4, 4)$, $L = 1/2 + 1/2 + 3/8 + 1/4 + 1/4 = 1.875$ bits. Exactly $H$ — because all probabilities are dyadic.
:::

::: {.exercise}
Show that $\sum_i 2^{-\ell_i} = 1$ for a *complete* prefix code (one where every internal node of the tree has two children).
:::

::: {.solution}
Replace every edge probability by $1/2$. A leaf at depth $\ell_i$ then has probability $2^{-\ell_i}$; since the leaves of a full binary tree partition the root event, these probabilities sum to 1. A tree with a missing child has a "hole" of probability $2^{-d}$ and gives strict inequality.
:::

::: {.exercise}
Is the code $\{0, 01, 011, 0111\}$ uniquely decodable? Is it a prefix code? Does it satisfy Kraft?
:::

::: {.solution}
Not a prefix code ($0$ is a prefix of all others). It is uniquely decodable: every codeword starts with $0$, so each $0$ marks the start of a new codeword and the number of following $1$s identifies it — but decoding needs one bit of lookahead. Kraft: $1/2 + 1/4 + 1/8 + 1/16 = 15/16 \leq 1$. By Kraft–McMillan, the prefix code $\{0, 10, 110, 1110\}$ (the reversed codewords) has the same lengths.
:::

::: {.exercise}
For the $p = 0.9$ coin, compare the expected length per toss of the Huffman code on blocks of $n = 1, 2, 3$ tosses with $H(X) = 0.469$.
:::

::: {.solution}
$n = 1$: 1 bit/toss. $n = 2$: probabilities $(0.81, 0.09, 0.09, 0.01)$; Huffman lengths $(1, 2, 3, 3)$, $L_2 = 0.81 + 0.18 + 0.27 + 0.03 = 1.29$, i.e. $0.645$ bits/toss. $n = 3$: $L_3 = 1.598$, i.e. $0.533$ bits/toss. The rate approaches $H$ as $n$ grows, consistent with $L_n/n < H + 1/n$.
:::

::: {.exercise}
A code designed for $q = (\tfrac12, \tfrac14, \tfrac18, \tfrac18)$ (lengths $1, 2, 3, 3$) is used on a uniform source $p = (\tfrac14, \tfrac14, \tfrac14, \tfrac14)$. Compute the expected length and check it equals $H(p) + D(p\|q)$.
:::

::: {.solution}
$L = \tfrac14(1 + 2 + 3 + 3) = 2.25$ bits. $H(p) = 2$ and $D(p\|q) = \tfrac14[\log\tfrac{1/4}{1/2} + \log 1 + 2\log\tfrac{1/4}{1/8}] = \tfrac14[-1 + 0 + 2] = 0.25$. Indeed $2 + 0.25 = 2.25$ (the code is complete, $z = 1$).
:::

## Callouts

::: {.callout-note}
The fixed-length source-coding theorem is *asymptotic*: it needs $n \sim \sigma^2/(\beta^2\delta)$. Symbol codes work with $n = 1$ but can waste up to one bit per symbol; coding blocks of $n$ symbols reduces this to $1/n$.
:::

::: {.callout-tip}
Useful mental picture: an optimal code assigns $\ell_i \approx -\log_2 p_i$, i.e. **codeword length = surprisal**. Conversely, every complete prefix code implicitly defines a probability model $q_i = 2^{-\ell_i}$.
:::

::: {.callout-important}
The most probable sequence is not typical. Typicality is about the *information content* $-\tfrac1n\log P$, not about the probability being large.
:::

::: {.callout-warning}
Universal codes give the *asymptotic* compression rate. On short inputs they often *expand* the data due to header overhead. Don't benchmark compressors on toy examples.
:::
